# Эксперименты с котировками
{: id="эксперименты-с-синтетическими-котировками" }

## Один набор параметров, 32 варианта движения цены
{: #monte-carlo }

Допустим, вы проверяете стратегию и хотите понять, насколько результат зависит от удачного выбора ценовой истории. Метод Монте-Карло позволяет снова и снова разыгрывать движение цены при одних и тех же предположениях. В этом примере у всех 32 рядов одинаковые начальная цена, волатильность и длительность. Различается только последовательность случайных движений.

```sh
python -m pricegenerator monte-carlo --seed 42 --paths 32 --horizon 120 --start 2025-01-06T00:00:00Z --timeframe-seconds 3600 --output ensemble.json --manifest ensemble-manifest.json --chart quantiles.html
python -m pricegenerator replay-ensemble ensemble-manifest.json --output replayed.json
```

Откройте **`quantiles.html`**. Свечи и объёмы относятся к первому ряду. Для трёх линий программа в каждом часу берёт цены закрытия **всех** рядов и располагает их по возрастанию. В последний, 120-й час среднее между 16-й и 17-й ценами, то есть медиана, равно **101,27**. Границы центральных 90% по модели — **75,01** и **150,46** (5-й и 95-й процентили). Для предыдущего часа те же три величины рассчитаны по другой выборке закрытий. Полоса описывает разброс на отдельный момент времени. У одной и той же траектории часть свечей может оказаться внутри полосы, часть — снаружи.

В `ensemble.json` записана максимальная просадка **цены** для каждой траектории. Чтобы рассчитать просадку **стратегии**, загрузите эти котировки в свой тестер и учтите позиции, цены сделок и издержки.

### Где посмотреть и скачать остальные траектории?
{: #paths }

Генератор рассчитывает все 32 ряда целиком. На обычном графике свечами и объёмом показан **ряд № 0**. Три линии рассчитываются по ценам закрытия всех рядов. В JSON сохраняются квантили, максимальная просадка каждой траектории и настройки для повторения опыта. Чтобы получить отдельный CSV для каждой траектории, потребуется экспорт.

Свечи и столбики объёма на рисунке относятся к ряду № 0. За свечами проходит 31 тонкая серая линия. Каждая соединяет часовые цены закрытия одного из остальных рядов. Голубая линия показывает 5-й процентиль, фиолетовая — медиану, золотистая — 95-й процентиль. Все три значения рассчитываются заново для каждого часа по 32 ценам закрытия.

[![Часовые свечи и объёмы ряда № 0, ещё 31 траектория серым и три цветные линии процентилей.](https://fuzzy-technologies.com/PriceGenerator/docs/assets/monte-carlo-32-paths.svg)](https://fuzzy-technologies.com/PriceGenerator/docs/assets/monte-carlo-32-paths.svg)

**[Скачать все 32 ряда в CSV одним архивом](https://fuzzy-technologies.com/PriceGenerator/docs/assets/monte-carlo-32-paths.zip)**. В файлах от `path-00.csv` до `path-31.csv` — по 120 часовых свечей. У каждой есть цены открытия и закрытия, максимум, минимум и объём.

Для собственного эксперимента запустите этот код в папке с `ensemble.json`, полученным командой выше. Программа прочитает исходные настройки, по номеру ряда восстановит его случайную последовательность и запишет все CSV в папку `paths`. Нумерация начинается с нуля.

```python
import json
from dataclasses import replace
from pathlib import Path

from pricegenerator import Generate, GenerationConfig, WriteCSV
from pricegenerator.monte_carlo import DerivePathSeed

report = json.loads(Path("ensemble.json").read_text(encoding="utf-8"))
config = GenerationConfig.FromDict(report["configuration"])
output = Path("paths")
output.mkdir(exist_ok=True)

for index in range(report["path_count"]):
    seed = DerivePathSeed(config.seed, index)
    candles = Generate(replace(config, seed=seed))
    WriteCSV(candles, output / f"path-{index:02d}.csv", volume_as_count=config.model == "regime_v3")
```

Чтобы увидеть отдельный ряд со свечами и объёмами, откройте его CSV обычной командой построения графика. Здесь выбран ряд № 17.

```sh
python -m pricegenerator chart paths/path-17.csv --analysis --output path-17.html --view
```

## Сравнить модель с историческими данными
{: #compare }

Подготовьте два CSV — с рыночной историей и с результатом моделирования. Укажите одинаковый интервал свечи и приведите объёмы к сопоставимым единицам. Например, объём в BTC можно сравнить с объёмом в BTC. Сначала выберите в каждом файле непрерывный участок без пропусков.

```sh
python -m pricegenerator compare observed.csv synthetic.csv --timeframe-seconds 3600 --output comparison.json
```

В `comparison.json` указаны волатильность, максимальная ценовая просадка, средний объём и другие показатели каждого ряда. При необходимости заранее задайте для выбранных показателей допустимые абсолютные отклонения в файле JSON и укажите его через `--tolerances`. Команда может выполниться успешно и при расхождении с эталоном. Для решения по каждому показателю смотрите поле `within_tolerance`.

## Насколько модель похожа на BTC/USD?
{: #bitstamp }

Базовый сценарий начинается с цены 100 и не привязан к биржевому инструменту. Для проверки на конкретном рынке мы взяли часовые свечи BTC/USD с Bitstamp. По **720 часам сентября 2024 года** оценили параметры модели `regime_v2`, а **744 часа октября** оставили для проверки. Во всех 16 прогонах волатильность часовых доходностей и средний часовой объём уложились в допуски, заданные по сентябрьским данным.

Средний объём оказался близок к биржевому, но за сходством средних скрывается важное различие. При этих настройках модель **каждый час** давала 71,93 BTC. На бирже за час в среднем торговалось 67,45 BTC, причём от часа к часу объём менялся. Его корреляция с модулем часовой доходности составила **0,522**. У постоянного объёма эту корреляцию вычислить нельзя. Для стратегии, которая торгует на всплесках объёма, в таком ряду пропадает сам сигнал.

Различалась и связь между движениями цены в соседние часы. На бирже автокорреляция квадратов часовых доходностей при сдвиге на один час составила 0,3345. В модели даже 95-й процентиль этого показателя по 16 прогонам составил лишь 0,0395.

Постоянный объём — особенность параметров именно этого эксперимента. В стандартном сценарии `regime_v3` объём меняется от свечи к свече и измеряется в условных целых единицах. [Исходные данные и результаты по каждому прогону (JSON)](https://fuzzy-technologies.com/PriceGenerator/docs/evidence/reference-bitstamp-holdout.json)

## Как передать эксперимент коллеге
{: #bundle }

В корне исходников той же версии, что и установленный пакет, выполните две команды. В качестве `pg-experiment` укажите новую папку.

```sh
python -I tools/experiment_bundle.py create pg-experiment
python -I tools/experiment_bundle.py verify pg-experiment
```

Первая команда сохранит два синтетических часовых ряда, их параметры, результаты сравнения, график по 32 траекториям и контрольные суммы файлов. Вторая команда проверит содержимое папки. Коллеге можно передать её целиком.

Откройте `pg-experiment/quantiles.html`, чтобы увидеть разброс цен. Для графика с индикаторами выполните `python -m pricegenerator chart pg-experiment/scenario.csv --analysis --output analysis.html --view`. Здесь всего 120 свечей. Если нужна средняя за 200 периодов, возьмите 240 свечей из [быстрого старта](https://fuzzy-technologies.com/PriceGenerator/ru/quick-start/).

## Сколько времени занимает генерация миллиона свечей?
{: #performance }

На сервере с AMD EPYC 9V74 под Linux один процесс Python сгенерировал **1 млн минутных свечей за 3,72 секунды** — около **269 тыс. свечей в секунду**. Вместе с записью в локальный CSV весь процесс занял **8,59 секунды**. Размер файла — 109,5 МБ. Для каждой свечи записаны время, четыре цены и целочисленный объём.

| Минутных свечей | Генерация в памяти | Запись в CSV | От начала генерации до закрытия файла |
| --------------: | -----------------: | -----------: | ------------------------------------: |
| 100 000         | 0,33 с             | 0,45 с       | 0,77 с                                |
| 1 000 000       | 3,72 с             | 4,87 с       | 8,59 с                                |

Для каждого размера выполнили пять запусков, каждый в отдельном процессе. В каждом столбце приведена своя медиана. Использовали пакет 2.2.1 с PyPI, CPython 3.14.10, pandas 2.3.3, NumPy 2.3.5 и `seed=42`. Засекали время вызовов `Generate` и `WriteCSV` с их штатной проверкой данных и буферизованной записью. Импорты и прогрев завершили до старта таймера, контрольную сумму файла считали после записи. График в замер не входил. На другом процессоре или диске время будет отличаться.

В одном ряду может быть до **1 млн свечей**. В одном эксперименте Монте-Карло допустимы от 2 до 10 000 траекторий и **до 1 млн свечей суммарно**. Например, для 32 траекторий предел составляет 31 250 свечей на каждую. Чтобы повторить замер у себя, скачайте скрипт и выполните `python -I measure_generation.py 1000000` в окружении с версией 2.2.1. [Скрипт замера](https://fuzzy-technologies.com/PriceGenerator/docs/evidence/measure_generation.py) · [Время всех запусков и контрольные суммы CSV (JSON)](https://fuzzy-technologies.com/PriceGenerator/docs/evidence/generation-speed-2.2.1.json)
