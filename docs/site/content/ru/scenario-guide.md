## Какие данные принимает пакет

Таблица содержит шесть столбцов в порядке
`datetime,open,high,low,close,volume`. Метки времени уникальны, строго
возрастают и приводятся к UTC с наносекундной точностью. Цены и объём
хранятся как конечные числа `float64`, объём неотрицателен. Для каждой
свечи должно выполняться `high >= max(open, close)` и
`low <= min(open, close)`. При импорте допустимы
нулевые и отрицательные цены, если эти условия выполнены. Генератор
по умолчанию выдаёт положительные цены.

Для проверки регулярного ряда укажите интервал между барами. Если в метках
времени брокера отсутствует смещение, задайте часовой пояс явно. Сохраняйте
реальные разрывы в истории. При обмене с MT5 проверьте минутную сетку,
целочисленные поля объёма и спред. Для тестирования на реальных тиках
понадобится отдельная тиковая история.

## Как модель рассчитывает цену и объём

У `regime_v2` два режима волатильности. Модель начинает в спокойном
режиме и перед каждой свечой может перейти в другой с вероятностью
`1 - regime_persistence`. Стандартное отклонение гауссовской составляющей
доходности в спокойном режиме равно `volatility`, а в режиме повышенной
волатильности — `volatility * regime_scale`. Параметры действуют на один бар.
При смене таймфрейма подберите их для нового интервала.

Модель сначала рассчитывает логарифмическую доходность
$r = \mu + \sigma Z + \sigma_0 s B Z_{\mathrm{shock}}$.
Здесь $\mu$ — дрейф `drift`, $\sigma$ — стандартное отклонение в текущем
режиме, $\sigma_0$ — базовая волатильность `volatility`, а $s$ — масштаб
скачка `shock_scale`. $Z$ и $Z_{\mathrm{shock}}$ — независимые
стандартные нормальные величины. Независимая величина Бернулли $B$ равна
единице с вероятностью `shock_probability`. При $B=1$ в доходность входит
слагаемое скачка.

Со второй свечи цена открытия равна цене закрытия предыдущей. Если
расчётная логарифмическая цена закрытия выходит за заданные границы,
модель отражает её внутрь допустимого диапазона. Поэтому итоговая
логарифмическая доходность может отличаться от $r$.

Длины теней рассчитываются от границ тела в логарифмах цены. Редкие
удлинения верхней и нижней тени моделируются независимо. Концы теней
ограничены заданным диапазоном цен. Объём — непрерывный показатель
активности. Его модель учитывает автокорреляцию шума в логарифмах объёма
и позволяет связать активность с абсолютной величиной фактической
доходности.

## Как проверить результат и повторить прогон

В каталоге примера выполните две команды.

```sh
python -I -m pricegenerator analyze prices.csv --output statistics.json
python -I -m pricegenerator chart prices.csv --output analysis.html --analysis --no-view
```

`analyze` записывает статистические показатели и объясняет, почему отдельные показатели
могут быть недоступны. `chart` создаёт интерактивный HTML-график
с индикаторами и сводкой. Его можно открыть локально.
[Показатели и условия расчёта](../../../analysis.md)

**Где кнопки индикаторов?** Пересоздайте HTML из того же CSV с флагом
`--analysis` или вызовите `Chart(prices, "chart.html", analysis=True)` в Python.
Откройте HTML в браузере. **Bollinger bands** показывают диапазон вокруг
скользящей средней, **SMA 50 / 200** — две средние, а **Midpoint** — середины
диапазонов свечей. Также доступны HMA, VWMA, PSAR, Alligator и Zig-Zag.
В разделе **Individual series** можно переключать отдельные линии.
Для SMA 200 нужно не менее 200 свечей.

Приблизьте участок колёсиком или рамкой (**Box zoom**). Кнопка **Light theme**
включает светлую тему, а **Export PNG** сохраняет выбранный вид. Под графиком
есть краткая сводка. Полный отчёт раскрывается по кнопке **Detailed statistics**.

![Офлайн-график свечей и объёмов с включёнными полосами Боллинджера и средними за 50 и 200 свечей](../../../assets/pricegenerator-chart-analysis.webp)

Сохраните тег или коммит, настройки вместе с `seed`, манифест, команду,
версии зависимостей и SHA-256 каждого файла экспорта. Контрольный хеш
OHLCV в манифесте относится к самим свечам. Хеш экспорта относится к
байтам файла и может зависеть от окружения. Примеры ниже содержат
команды и параметры, необходимые для воспроизведения иллюстраций.
В записи работы CLI использован отдельный ряд из 120 свечей.
[Рыночный график](../../../examples/modern-market.md) ·
[Привязка индикаторов к свечам](../../../examples/modern-indicator-alignment.md) ·
[Запись работы CLI](../../../examples/cli-demo.md)

## Для чего подходят исследовательские функции

- Калибровка, бутстрэп и заданные стресс-сценарии доступны через
  экспериментальные API. Примеры можно повторить на синтетических
  данных. [Исследовательские модели](../../../research-models.md)
- В ансамбле Монте-Карло квантиль цены рассчитывается отдельно для каждой
  свечи по всем траекториям. Полоса квантилей зависит от модели и
  описывает разброс в отдельные моменты. Вероятность попадания в эту
  полосу на всём пути требует отдельной оценки. [Монте-Карло](../../../monte-carlo.md)
- На CPython 3.13–3.15 можно подключить экспериментальную нечёткую
  диагностику. Она рассчитывает одну оценку по двум отношениям
  волатильности и активности к опорным значениям. Генерация свечей
  идёт независимо от этой оценки. [Нечёткая диагностика](../../../fuzzy-diagnostics.md)
- При сравнении с биржевой историей проверяйте отдельно структуру свечей,
  распределения показателей и зависимости внутри ряда. Описание
  исторического примера содержит источник данных, допущения и ограничения.
  [Сравнение с историей](../../../reference-comparison.md) ·
  [Правила статистической проверки](../../../adr/0005-statistical-validation-and-realism-claims.md)

Базовая модель подходит для контролируемых тестов программ, которые
работают с OHLCV, и для стресс-сценариев. Для моделирования стакана заявок,
спреда, исполнения ордеров и торговых сессий нужны отдельные компоненты.
Качество прогноза и доходность стратегии проверяют отдельно на рыночных
данных.

Соберите справочник из того же коммита, чтобы сверить функции, доступные
из `pricegenerator`, и их сигнатуры.
[Сборка справочника Python API](../../../development.md#build-the-public-api-reference)
